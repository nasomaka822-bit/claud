# Мониторинг тендеров на зачистку резервуаров

Скрипт раз в 30 минут проверяет ленты и страницы с тендерами. Новые тендеры на зачистку, пропарку и дегазацию резервуаров со светлыми нефтепродуктами он присылает в Telegram и (или) на почту. По умолчанию приходят только тендеры из ЮФО и те, у которых регион определить не удалось.

## Откуда берутся тендеры

Всего 31 источник, включено 28. Как устроен каждый, проверено 27.09.2026.

- **РосТендер.** RSS-ленты категорий «зачистка резервуаров», «зачистка емкостей», «утилизация нефтешламов», «зачистка нефтепроводов», «демонтаж резервуаров» и «закупки АЗС». В ленте лежат только тендеры последних дней, поэтому раз в 2 часа скрипт дополнительно читает страницы категорий, по 20 последних тендеров. Ещё читаются страница отрасли «Промышленные резервуары и ёмкости» (её RSS-лента не обновляется с 2025 года), закупки агрохолдингов со всей России и МЭЗ «Юг Руси». РосТендер собирает закупки из ЕИС, с ЭТП ГПБ, ТЭК-Торга, Сбербанк-АСТ, B2B-Center, РТС-тендер и сайтов компаний. Регион тендера скрипт берёт из адреса на РосТендере, поэтому чужие регионы отсеиваются точно.
- **ЕИС (zakupki.gov.ru), 8 поисковых RSS-лент.** Закупки по 44-ФЗ и 223-ФЗ на этапе подачи заявок, в том числе госкомпаний: Роснефти, Транснефти, Газпрома, РЖД, портов.
- **Страницы закупок компаний.**
  - ЛУКОЙЛ: список отсортирован по сроку подачи, а не по дате публикации, поэтому скрипт раз в 4 часа читает все страницы, около 60.
  - «Степь»: только закупки, по которым идёт приём предложений, раз в час.
  - Астон, ОТЭКО (Таманьнефтегаз). Агрокомплекс им. Ткачёва, НМТП и Черноморнефтегаз выключены: сайты не отвечают или сменили адрес.
  - ЕвроХим: только заводы в ЮФО, ЕвроХим-БМУ в Белореченске и ВолгаКалий.
  - Зерновой терминал КСК в Новороссийске: на странице весь архив с 2014 года, уведомления приходят только о закупках, начатых за последние `max_age_days` дней.

Сайты «Юг Руси» и «Магнита» строят список закупок JavaScript'ом, скрипт их не видит. «Юг Руси» подключён через РосТендер, «Магнит» убран: тендеров на зачистку у него не нашлось. В личные кабинеты площадок скрипт не заходит. Закупки с ЭТП ГПБ, ТЭК-Торга, Сбербанк-АСТ и B2B-Center приходят через РосТендер и ЕИС.

## Установка на Windows

1. Установите Python 3.11 или новее с сайта python.org. В первом окне установщика отметьте «Add python.exe to PATH».
2. Распакуйте архив в папку, например `C:\TenderMonitor`.
3. Откройте эту папку в Проводнике, в адресной строке наберите `cmd` и нажмите Enter. В открывшемся окне выполните:

   ```
   python -m pip install -r requirements.txt
   ```

## Настройка Telegram

1. В Telegram найдите бота **@BotFather**, отправьте ему `/newbot` и придумайте имя. В ответ придёт токен вида `1234567890:AAH...`.
2. Откройте `config.toml` в Блокноте и впишите токен в строку `bot_token = ""` между кавычками.
3. Найдите в Telegram своего нового бота и нажмите «Запустить».
4. Выполните команду ниже. Скрипт найдёт ваш chat_id и сам впишет его в настройки.

   ```
   python tender_monitor.py --get-chat-id
   ```

5. Проверьте отправку, должно прийти тестовое сообщение:

   ```
   python tender_monitor.py --test
   ```

Уведомления можно получать и в группу: добавьте бота в группу, напишите там любое сообщение и снова выполните `--get-chat-id`.

## Почта (по желанию)

В разделе `[email]` поставьте `enabled = true` и заполните адрес, логин и получателей. Для Яндекса оставьте `smtp.yandex.ru`, порт 465, и создайте пароль приложения: id.yandex.ru → «Безопасность» → «Пароли приложений». Обычный пароль от почты не подойдёт.

## Сертификат для ЕИС

С июля 2026 года zakupki.gov.ru работает на сертификате Минцифры, которого нет в Python. Скачайте его командой:

```
python tender_monitor.py --setup-cert
```

Если скачать не получилось, возьмите «Корневой сертификат» и «Выпускающий сертификат» в формате PEM на странице gosuslugi.ru/crt и положите их рядом со скриптом под именами `russian_trusted_root_ca_pem.crt` и `russian_trusted_sub_ca_pem.crt`. Скрипт доверяет этому сертификату только для сайтов в зонах .ru, .su и .рф.

Некоторые сайты компаний отдают свой сертификат без промежуточного, и Python выдаёт ошибку `unable to get local issuer certificate`, хотя браузер открывает сайт без предупреждений. В этом случае скрипт, как и браузер, сам скачивает недостающий промежуточный сертификат по ссылке из сертификата сайта и кладёт его в папку `issuer_certs`. Проверка подлинности при этом не отключается, а скачанный сертификат применяется только к своему сайту. Корневые сертификаты из интернета скрипт не принимает. На Windows он может взять корневой сертификат из системного хранилища, если Windows ему доверяет. Если по ссылке из сертификата лежит не тот сертификат (с тем же именем, но другим ключом), скрипт ищет подходящий в хранилище промежуточных сертификатов Windows. Сертификат сайта скрипт читает тем же путём, каким загружает страницы, в том числе через прокси. Если цепочка так и не сошлась, в отчёте `--probe` будет написано почему: какой сертификат показал сайт, кем он выдан и идут ли запросы через прокси.

Если скрипт так и не смог достроить цепочку, возьмите промежуточный сертификат из браузера. Откройте сайт в Chrome или Edge, нажмите значок слева от адреса → «Безопасное подключение» → «Действительный сертификат» → вкладка «Подробности». В «Иерархии сертификатов» выберите средний сертификат, нажмите «Экспорт» и сохраните его в папку `issuer_certs` рядом со скриптом под именем сайта с расширением `.cer`, например `aston.ru.cer` или `www.oteko.ru.cer`. Такие файлы скрипт не меняет.

ЕИС открывается только с российских IP-адресов. Если скрипт работает на зарубежном сервере, укажите российский прокси в `proxy` раздела `[settings]`.

## Проверка источников

```
python tender_monitor.py --probe
```

Команда заходит в каждый источник и показывает:
- сколько тендеров удалось достать;
- три первых тендера с датой, местом, ценой и регионом;
- сколько тендеров подходит по словам и сколько из них пришло бы уведомлением.

Если источник не работает, рядом будет причина и что делать: поставить сертификат, включить прокси, выключить источник. Проверка занимает несколько минут, потому что между запросами к одному сайту скрипт делает паузу. Ничего не отправляется и не запоминается.

Отчёт сохраняется в файл `probe_report.txt` рядом со скриптом, а первые страницы сайтов компаний — в папку `probe_pages`. Если какой-то источник выдаёт ошибку или странные названия, пришлите отчёт и страницу этого источника из `probe_pages`, и разбор можно будет поправить. Проверить один источник: `python tender_monitor.py --probe ЛУКОЙЛ` (подходит любое слово из названия источника).

## Первый запуск

```
python tender_monitor.py --dry-run
```

Эта команда покажет подходящие тендеры, которые есть в источниках сейчас. Ничего не отправляется и не запоминается.

```
python tender_monitor.py
```

Первая настоящая проверка пришлёт сообщение «Мониторинг тендеров запущен» и сводку подходящих тендеров, которые уже есть в лентах. Дальше будут приходить только новые.

## Запуск по расписанию

**Проще всего:** дважды щёлкните `start_monitor.bat`. Откроется окно, и скрипт будет проверять источники каждые 30 минут, пока оно открыто. Это то же самое, что команда:

```
python tender_monitor.py --loop
```

**Планировщик заданий Windows:** проверка будет идти в фоне без окна. Узнайте путь к pythonw командой `where pythonw` и выполните одной строкой, подставив свои пути:

```
schtasks /Create /TN "TenderMonitor" /SC MINUTE /MO 30 /TR "\"C:\Users\Имя\AppData\Local\Programs\Python\Python312\pythonw.exe\" \"C:\TenderMonitor\tender_monitor.py\""
```

Удалить задание: `schtasks /Delete /TN "TenderMonitor" /F`. Компьютер при этом должен быть включён. Чтобы уведомления приходили круглосуточно, скрипт можно поставить на недорогой сервер в России.

**Linux-сервер (cron):**

```
*/30 * * * * cd /opt/tender_monitor && /usr/bin/python3 tender_monitor.py >> cron.log 2>&1
```

## Raspberry Pi и управление из Telegram

На Raspberry Pi скрипт работает как Telegram-бот: проверяет источники по расписанию (по умолчанию в 09:00 и 17:00 по Москве), после каждой проверки присылает короткий итог и слушает команды в вашем чате. Подходит Raspberry Pi OS 12 (Bookworm) и новее. Raspberry Pi должен быть в России: ЕИС открывается только с российских IP-адресов.

1. Скопируйте папку со скриптом на Raspberry Pi, например в `/home/pi/TenderMonitor`. Возьмите `config.toml`, где уже вписаны `bot_token` и `chat_id`, и `tender_monitor.db`, чтобы не получать уже присланные тендеры заново.
2. В терминале Raspberry Pi выполните:

   ```
   cd ~/TenderMonitor
   bash install_pi.sh
   ```

   Скрипт установит библиотеки, скачает сертификат Минцифры и создаст службу `tender-monitor`. Служба запускается сама при включении Raspberry Pi и перезапускается после сбоя. Когда всё готово, бот пишет в чат «Бот мониторинга тендеров запущен».

Команды в чате с ботом:

| Команда | Что делает |
|---|---|
| `/check` | проверить источники сейчас; в конце придёт итог |
| `/status` | расписание, последняя проверка, настройки, источники с ошибкой |
| `/last` | 10 последних присланных тендеров |
| `/time 09:00 17:00` | проверять в это время (московское); `/time сброс` — как в `config.toml` |
| `/regions все` / `/regions юфо` | присылать тендеры по всей России или только ЮФО |
| `/unspecified да` / `нет` | присылать ли тендеры, где вид нефтепродукта не указан |
| `/phrase название` | проверить, пришёл бы тендер с таким названием |
| `/pause` / `/resume` | остановить или возобновить проверки по расписанию |
| `/version` | версия скрипта и библиотек |

Бот отвечает только в чат, указанный в `chat_id`. Настройки, изменённые из чата, хранятся в `tender_monitor.db` и действуют поверх `config.toml`.

Управлять службой на Raspberry Pi:

```
sudo systemctl status tender-monitor     # работает ли
sudo systemctl restart tender-monitor    # перезапустить, например после правки config.toml
sudo systemctl stop tender-monitor       # остановить
tail -f ~/TenderMonitor/tender_monitor.log
```

Режим бота работает и на Windows: `python tender_monitor.py --bot`.

## Как настроить поиск

Все настройки лежат в `config.toml` с комментариями. Файл перечитывается при каждой проверке.

- **Правила `[[rules]]`.** Тендер подходит, если в названии рядом стоят слово-действие (`actions`) и слово-объект (`objects`) или встречается фраза из `words`. Пишите начала слов: `чистк` найдёт «зачистка», «очистки», «прочистку». Правила «Демонтаж и ремонт резервуаров» и «Градуировка и диагностика резервуаров» выключены. Чтобы включить, поставьте у них `enabled = true`.
- **Только светлые нефтепродукты `[product]`.** После правил скрипт смотрит, какой продукт назван в тендере. Бензин, дизель, ДТ, керосин, авиатопливо, АЗС, бензовозы (`light`) — тендер приходит. Мазут, нефть, масла, битум, вода, канализация, очистные сооружения (`dark`) — пропускается. Если продукт не назван («зачистка резервуаров хранения», «ГСМ», «нефтепродукты»), тендер приходит с пометкой «вид нефтепродукта не указан». Чтобы такие не приходили, поставьте `send_unspecified = false`. Отключить отбор по продукту: `enabled = false`.
- **Исключения `[exclude]`.** Тендер пропускается, если в названии есть одно из этих слов. Если не работаете с газом, добавьте «газгольдер», «суг», «пропан».
- **Регионы.** Чтобы получать тендеры по всей России, поставьте `only_my_regions = false`. Регион определяется так:
  - у РосТендера — по адресу тендера (`rostender_regions`);
  - у ЕИС — по коду в номере закупки (`region_codes`);
  - у остальных — по словам в месте поставки или названии заказчика (`region_words`).

  Если меняете регионы, поменяйте все три списка.
- **Проверить фразу:**

  ```
  python tender_monitor.py --check "Оказание услуг по зачистке резервуаров АЗС в г. Таганрог"
  ```

## Как добавить источник

Скопируйте блок `[[sources]]` в конце `config.toml` и поменяйте его.

- **Поиск в ЕИС:** `type = "eis"` и фраза в `query`. Можно вставить и свою RSS-ссылку с сайта ЕИС (кнопка RSS под результатами расширенного поиска) с `type = "rss"`.
- **Категория или заказчик на РосТендере:** на странице категории или заказчика (например, `rostender.info/category/tendery-agroholding-step`) есть ссылка RSS вида `https://rostender.info/rss-category-NNN.xml`. Укажите её с `type = "rss"`. Также можно добавить и саму страницу с `type = "html"` и `every_minutes = 120`. Это лучший способ подключить компанию, чей сайт строит список закупок JavaScript'ом.
- **Страница компании:** `type = "html"` и адрес страницы со списком закупок.

Настройки для сложных страниц:
- `page_url` и `pages` — читать несколько страниц списка;
- `every_minutes` — проверять реже;
- `item_link`, `item_marker` или `item_block` с `item_title` — как найти на странице отдельные тендеры: по ссылкам на карточки, по тексту, который есть в каждом тендере, или по CSS-селекторам блока и названия;
- `require` — брать только тендеры нужных дочерних обществ.

Примеры есть в `config.toml`. После добавления проверьте источник: `python tender_monitor.py --probe "название источника"`.

Новый источник при первом чтении только запоминает текущие тендеры и присылает о них одну сводку, а не десятки сообщений.

## Что полезно знать

- Если источник не работает 3 проверки подряд, придёт предупреждение, а когда он заработает снова, придёт второе сообщение. Так вы узнаете, что сайт сменил адрес ленты или вёрстку.
- Если Telegram и почта недоступны, уведомления не потеряются: скрипт отправит их при следующей проверке.
- Один и тот же тендер из РосТендера и ЕИС приходит один раз.
- Если страница компании перестала отдавать тендеры (сайт поменял вёрстку или перешёл на JavaScript), скрипт считает это ошибкой. После 3 таких проверок подряд придёт предупреждение.
- Страницы, закрытые в robots.txt, скрипт пропускает, поэтому сайт КТК не включён.

## Самообслуживание

В режиме бота (`--bot`, служба на Raspberry Pi) скрипт сам следит за собой и пишет в чат, что сделал.

Сам исправляет:
- **сертификаты Минцифры**: скачивает заново, если их нет, если до окончания меньше 30 дней или если ЕИС выдала ошибку сертификата. Принимается только действующий сертификат с именем «Russian Trusted», скачанный с официального адреса;
- **сертификаты сайтов**: недостающий промежуточный сертификат скачивает сам; истёкший или истекающий удаляет и скачивает свежий;
- **сломанный источник**: после 3 ошибок подряд проверяет его реже (через 1, 2, 4… часа, но не реже раза в сутки) и сообщает, когда он снова заработает;
- **зависшую проверку**: если проверка идёт дольше 45 минут, бот перезапускается;
- **сбой или выключение питания**: служба поднимает бота заново, бот сообщает о перезапуске и последней ошибке из журнала;
- **испорченную базу**: при запуске проверяет её и при порче восстанавливает последнюю копию.

Сам обслуживает, раз в сутки:
- удаляет страницы `probe_pages` старше 30 дней и файлы прошлых версий;
- делает копию базы в `backups` (хранятся последние 7), раз в месяц сжимает базу;
- когда на диске меньше 300 МБ, чистит всё лишнее и сообщает об этом;
- раз в месяц обновляет библиотеки Python (`auto_update`). После обновления прогоняет тесты; если что-то сломалось, возвращает прежние версии, если всё в порядке — перезапускается;
- раз в неделю обновляет сам скрипт из git (`auto_update_code`, по умолчанию выключено; работает, только если папка — копия git-репозитория), тоже с тестами и откатом.

Чего скрипт сам не исправит — **смену вёрстки сайта**. Переписать разбор чужой страницы автоматически нельзя без риска присылать мусор. Когда страница перестаёт разбираться или вдруг отдаёт намного меньше записей, бот сохраняет её в `probe_pages` и пишет, какой файл прислать для исправления.

Что может сломаться за месяцы работы, описано в `AUDIT.md`.

## Файлы

- `tender_monitor.py`: сам скрипт.
- `config.toml`: настройки.
- `start_monitor.bat`: запуск постоянной проверки двойным щелчком (Windows).
- `install_pi.sh`: установка на Raspberry Pi как служба с Telegram-ботом.
- `AUDIT.md`: аудит, риски на полгода работы, планы развития, регламент обслуживания.
- `backups/`: копии базы за последние 7 дней.
- `probe_report.txt`: отчёт последней проверки источников (`--probe`).
- `probe_pages/`: страницы сайтов компаний из последней проверки источников.
- `issuer_certs/`: промежуточные сертификаты для сайтов, не отдающих их сами: `.crt` скрипт докачивает сам, `.cer` вы сохраняете из браузера.
- `tests/`: тесты разбора каждого типа источника на сохранённых образцах страниц. Интернет для них не нужен. Запуск: `python -m unittest discover -s tests -v`.
- `tender_monitor.db`: база уже увиденных тендеров. Удалите её, чтобы начать с чистого листа.
- `tender_monitor.log`: журнал проверок.

## Все команды

| Команда | Что делает |
|---|---|
| `python tender_monitor.py` | одна проверка (для планировщика) |
| `python tender_monitor.py --loop` | проверять постоянно |
| `python tender_monitor.py --bot` | проверять по расписанию и слушать команды в Telegram |
| `python tender_monitor.py --probe` | проверить каждый источник и сохранить отчёт |
| `python tender_monitor.py --dry-run` | показать подходящие тендеры, ничего не отправляя |
| `python tender_monitor.py --test` | отправить тестовое уведомление |
| `python tender_monitor.py --get-chat-id` | узнать chat_id для Telegram |
| `python tender_monitor.py --setup-cert` | скачать сертификат Минцифры |
| `python tender_monitor.py --check "текст"` | проверить, пройдёт ли название фильтр |
| `python tender_monitor.py --status` | состояние источников |
